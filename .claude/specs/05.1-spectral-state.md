## Goal

Spec 05's calendar/cyclical features (`hour_sin/cos`, `dow_sin/cos`, `doy_sin/cos`) assume the
daily, weekly and annual cycle shape is fixed. A rolling spectral summary instead asks: **how
strong is the usual cycle right now, and is it breaking down?** A weakening daily/weekly pattern —
falling energy share, rising entropy — is a plausible signal that a day is drifting into
irregular, potentially stress-prone territory, which is exactly the kind of day this project wants
to flag. This is a candidate addition to test, not an assumed improvement: nothing so far has shown
it beats the plain cyclical encodings on a chronological fold.

## Scope

### IN (when un-parked)

- A trailing, fixed-length window (e.g. 28 days) of `residual_load`, ending strictly before the
  target day's first hour — same origin-safety rule as spec 05.
- An FFT (or Welch) over that window, restricted to pre-declared bands (daily, half-daily, weekly)
  — no full-record peak search, no band chosen after seeing outcomes.
- Candidate features per origin: band energy share (daily / weekly / half-daily), dominant-band
  amplitude, spectral entropy, and reconstruction error of a harmonic fit at the declared periods.
- A **future-poison test**: recomputing the state at two origins that differ only by data after the
  later origin, and asserting the earlier origin's state is unchanged — the check spec 05.1 borrows
  directly from Hari's notebook, because it is the cheapest way to catch a leakage bug in a rolling
  spectral estimator.
- Scoring: refit the spec 05 baseline model with and without the spectral columns, on the same
  folds, and report whether it improves MAE/RMSE without degrading the tail — the same bar spec 05
  itself does not yet formalise but this addition should be held to.

### OUT

- Anything spec 05 rules out (no model fitting happens in spec 05 itself, so this section's
  scoring step is the first place either spec actually trains a model — flag this dependency
  explicitly if un-parked before spec 06 exists).
- Full-record FFT for feature purposes (diagnostic-only, kept in EDA notebooks, not a feature).
- Interaction terms crossing spectral state with calendar features (`S4_CONTEXT_MODULATED_HARMONICS`
  in Hari's notebook) — a further extension, not part of this spec even if un-parked.
- Harmonic regression coefficients as standalone features — only the summary statistics above.
- Any of Hari's notebook's other families (intervention clocks, control-theory state, fold-promotion
  gates).

## Open questions before this can be run

- Which bands to pre-declare (daily, half-daily, weekly — or fewer).
- Whether scoring happens inside this spec (informally) or waits for a real spec 06 modelling
