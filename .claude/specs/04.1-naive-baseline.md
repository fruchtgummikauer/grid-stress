## Goal

Put SMARD's forecast error in context: how much better is it than a forecast that needs no model at
all? A naive baseline is not part of the core product. It is interesting because it shows how much
of SMARD's accuracy is "free" (repeating yesterday / last week) and how much is real forecasting
skill, and it gives our own model a second, lower bar.

## Scope

### IN (when un-parked)

- Candidate naive forecasts of `residual_load`, `grid_load` and `renewables`:
  - **Weekly persistence** — same local hour, 7 days earlier (`D−7`). Available before SMARD issues
    its day-ahead forecast, so it is a fair comparison.
  - **Daily persistence** — same local hour, 1 day earlier (`D−1`). Only partly fair: SMARD's
    load forecast is published by 10:00 and its wind + solar forecast by 18:00 on `D−1` (see spec 04,
    Data), so the `D−1` actuals after those times were not available to SMARD. State this if used.
- The same metrics, slices and `window_metrics` helper as spec 04, on pairwise-complete hours.
- A skill score `1 − MAE_forecast / MAE_naive` for SMARD (and later our model) against each baseline.

### OUT

- Anything spec 04 rules out.
- Tuned or fitted baselines (seasonal averages, regressions). Those are models.
