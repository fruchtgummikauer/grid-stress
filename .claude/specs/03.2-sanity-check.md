## Goal

Reproduce a deliberately small slice of [01-Simple-EDA.md](01-Simple-EDA.md)'s data-quality
audit directly inside `team-EDA.ipynb`, so this notebook does not depend on
`EDA-simple-claude.ipynb` having been run first, plus a new one-week physical-plausibility plot
the team asked for, adapted from `EDA-hari.ipynb` cell 14 rather than copied from a source cell
that itself carries no tag.

## Scope

### IN

- Missing-value and duplicate-timestamp counts.
- Value-range sanity checks (non-negative generation, positive `grid_load`, night-solar
  tolerance).
- The first fully valid Monday–Sunday week, found programmatically and plotted twice.

### OUT

- The residual-load identity check (`residual_load` vs. `grid_load - renewables`) — its source
  cell in `EDA-simple-claude.ipynb` (cell 27) carries no tag, so it is excluded under the
  project-wide no-tag rule; see Edge cases.
- Any other check from [01-Simple-EDA.md](01-Simple-EDA.md)'s fuller audit (the gap listing, the
  dtype/`describe()` printout, ...). This section reproduces exactly two of that spec's checks,
  not its whole audit.
- `EDA-robert.ipynb`'s raw post-load lineplot and DST-gap timeline — both untagged, excluded.

## Behaviour

1. Report missing values per column and the duplicate-timestamp count. Both are expected to be
   zero; state the zero explicitly as a finding rather than omitting the check because the answer
   is uninteresting.
2. Run the value-range checks from [01-Simple-EDA.md](01-Simple-EDA.md) Behaviour 8: generation
   series (`wind_off`, `wind_on`, `solar`) non-negative, `grid_load` strictly positive, night-time
   `solar` below 0.5 % of the series maximum rather than exactly zero. Report any real violation
   with its timestamps.
3. Find the first fully valid **Monday 00:00 → Sunday 23:00** week: the first 168-row run, aligned
   to the ISO week, in which all eight `SERIES` columns are non-null. Search programmatically —
   do not hand-pick a week, and do not assume the record's very first calendar week qualifies (the
   record can open mid-week or mid-gap).
4. Plot that week twice, in MWh: one figure with the five physical series (`wind_off`, `wind_on`,
   `solar`, `grid_load`, `residual_load`), one with the three forecast series
   (`fc_gen_wind_solar`, `fc_grid_load`, `fc_res`). Adapted from `EDA-hari.ipynb` cell 14's
   one-week plausibility plot, which used a separately-downloaded, GW-scaled dataset — this
   version runs on `time_series` in the project's native MWh.
5. Self-check: assert the found week spans exactly 168 consecutive hourly rows from a Monday
   00:00 to the following Sunday 23:00 with no internal gap, and that both plots in Behaviour 4
   cover the identical date range.

## Data

No series beyond [03.1](03.1-setup.md)'s `SERIES`/`DERIVED` are needed.

## Edge cases

- **Night-time solar is near-zero, not zero.** Reuse the 0.5 %-of-maximum tolerance from
  [01-Simple-EDA.md](01-Simple-EDA.md) Behaviour 8; a strict `== 0` check produces thousands of
  false "violations" that are measurement noise, not data-quality problems.
- **The search must be programmatic and must not assume week 1 works.** The record can open
  mid-week or with an early gap; the first *fully valid* week is not necessarily the first
  *calendar* week.
- **Untagged exclusions relevant here.** `EDA-simple-claude.ipynb`'s residual-load identity-check
  histogram (cell 27) is excluded — no tag on that cell. `EDA-robert.ipynb`'s raw post-load
  lineplot (cell 8, labelled "Example Plot" in the source notebook) and its styled DST-gap
  timeline (cell 18) are excluded for the same reason. `EDA-hari.ipynb`'s own one-week
  plausibility plot (cell 14) is excluded as a *source cell* — untagged — but its idea survives,
  rebuilt fresh, as Behaviour 4. See
  [03-combined-cherry-picked-eda.md](03-combined-cherry-picked-eda.md) for the full cross-section
  exclusion list.
- **Missing data file.** Handled in [03.1-setup.md](03.1-setup.md); this section assumes loading
  already succeeded.

## Acceptance criteria

- [ ] Missing-value and duplicate-timestamp counts are reported, including an explicit zero where
      that is the result.
- [ ] The value-range checks run with the stated night-solar tolerance, and any real violation is
      listed by timestamp.
- [ ] The first fully valid Monday–Sunday week is found by code, not named as a literal date in
      the notebook.
- [ ] Both the physical-series and forecast-series plots cover that same week, in MWh.
- [ ] The residual-load identity check does **not** appear in this section (or anywhere in the
      notebook).
- [ ] `EDA-robert.ipynb`'s raw lineplot and DST-gap timeline do **not** appear.
- [ ] The self-check confirms the found week is exactly 168 rows, Monday through Sunday, with no
      internal gap.

## Out of bounds

- The residual-load identity check, the DST-gap timeline, and any data-quality view beyond
  Behaviour 1–2 — deliberately cut; see Edge cases.
- Any threshold or flag on the value-range checks — a violation is reported, not filtered or
  corrected.
- Everything [03-combined-cherry-picked-eda.md](03-combined-cherry-picked-eda.md) rules out
  globally.
