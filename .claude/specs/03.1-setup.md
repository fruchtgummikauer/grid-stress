## Goal

Establish the one shared `time_series` DataFrame, helper functions and dynamic-year convention
that every other section of the combined notebook depends on, so
[03.2](03.2-sanity-check.md)–[03.7](03.7-context-appendix.md) can each assume it exists rather
than re-deriving it. No plot lives in this section — it is pure setup.

## Behaviour

1. Resolve the data directory by walking upward from `Path.cwd()` until a `data/` folder is
   found, so the notebook runs unmodified whether started by Jupyter from `notebooks/01_eda/` or
   by nbconvert from the repo root. Fail with a clear message naming
   `notebooks/API-connection.ipynb` if `data/smard.csv` is not found.
2. Read `data/smard.csv` (`delimiter=";"`, `encoding="utf-8-sig"`), convert every numeric column
   from German-decimal text to `float`, rename columns to the project's snake_case names, and
   build `time_series` as a sorted, `DatetimeIndex`-indexed frame — the same method
   `EDA-simple-claude.ipynb` uses for its `ts`, renamed. Assert every `SERIES` column is `float`
   with a positive `is_float_dtype` check, not `!= object`: an unconverted German-decimal column
   can land as `StringDtype` under pandas 3, which `!= object` would wave through.
3. Define `SERIES` (the eight data columns) and `DERIVED` (`renewables`, `year`, `month`, `hour`,
   `dow`, `is_weekend`, `date`, `season`, `season_year`, `spans_gap`), and assert
   `list(time_series.columns) == SERIES + DERIVED` immediately after adding them.
4. Copy `period_mean`, `period_energy`, `_complete_periods`, `style_timeseries` (`ylabel`
   required), `seasonal_plot` (`ylabel` honoured, the discarded-parameter bug fixed),
   `DAY_NAMES = ["Mon", "Tue", "Wed", "Thu", "Fri", "Sat", "Sun"]`, and the meteorological season
   mapping with the December-to-next-year rule (`season_year = year + (month == 12)`) from
   `EDA-simple-claude.ipynb`, unchanged in behaviour.
5. Compute `YEARS = sorted(time_series["year"].unique())` immediately after loading. Every later
   section derives its own year lists, anchor years, and colour-per-year mappings from `YEARS` or
   `time_series.index` — no sub-spec may write a literal calendar year into code.
6. Record `LOADED = {"rows": len(time_series), "start": time_series.index.min(), "end":
   time_series.index.max()}` right after loading, so
   [03.7](03.7-context-appendix.md)'s closing self-check can detect whether anything mutated
   `time_series` between here and the end of the notebook.
7. Run an initial self-check: dtypes are `float` across `SERIES`, the index is sorted and unique,
   and `time_series` carries exactly `SERIES + DERIVED` and no other column.

## Data

Source file: `data/smard.csv`, produced by `notebooks/API-connection.ipynb`. Format: `sep=";"`,
`decimal=","`, `utf-8-sig`, one header row. Extent is not assumed fixed — see
[03-combined-cherry-picked-eda.md](03-combined-cherry-picked-eda.md) for why.

| CSV column | snake_case | Unit |
|---|---|---|
| `timestamp` | `timestamp` | — |
| `Wind Offshore` | `wind_off` | MWh |
| `Wind Onshore` | `wind_on` | MWh |
| `Solar` | `solar` | MWh |
| `Grid Load` | `grid_load` | MWh |
| `Residual Load` | `residual_load` | MWh |
| `Forecast Wind + Solar` | `fc_gen_wind_solar` | MWh |
| `Forecast Grid load` | `fc_grid_load` | MWh |
| `Forecast Residual Load` | `fc_res` | MWh |

`DERIVED`: `renewables` (`wind_on + wind_off + solar`), `year`, `month`, `hour`, `dow`,
`is_weekend`, `date`, `season`, `season_year`, `spans_gap` (index step > 1 h).

## Edge cases

- **Missing data file.** A fresh clone has no `data/smard.csv`. Behaviour 1 fails with a clear,
  actionable message rather than a raw `FileNotFoundError` deep inside `pd.read_csv`.
- **Notebook depth.** `team-EDA.ipynb` lives in `notebooks/01_eda/`, one level deeper than
  `EDA-simple-claude.ipynb`'s `notebooks/`. A fixed `"../../data/smard.csv"` breaks if the
  notebook is ever run from a different working directory — walk upward instead of hardcoding a
  depth.
- **German decimal format.** A silent failure mode is a column landing as `object` (or, under
  pandas 3, `StringDtype`) with every later aggregate looking plausible but wrong. Behaviour 2's
  dtype assert exists specifically to catch this immediately after loading.
- **Dynamic year range.** `data/smard.csv`'s extent may still change — the team intends to widen
  the fetch back to 2019. `YEARS` must be recomputed from the loaded data every run; nothing
  downstream may assume either the old or the new extent.
