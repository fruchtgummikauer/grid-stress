## Goal

Spec 05 builds a leakage-safe feature set for a forecast origin at **00:00 on `DAY`**. The
regression notebook (spec 06) forecasts from an earlier origin, the **availability cutoff** on
`DAY−1`:

| | Spec 05 | Spec 06 (governs here) |
|---|---|---|
| Origin | 00:00 on `DAY` | `AVAILABILITY_CUTOFF = ISSUE_TIME − actuals_lag` |
| Last usable actual | 23:00 on `DAY−1` | the row stamped `AVAILABILITY_CUTOFF − resolution` on `DAY−1` |

With the regression notebook's current `DATA_INFO` (issue 18:00, `actuals_lag = 2 h`), the cutoff is
16:00 and the last usable actual row is 15:00 on `DAY−1`. Five of spec 05's twelve features read
`DAY−1` after that row, so they leak under spec 06's setting: `residual_load_lag_24h`,
`vre_capacity_factor_lag_24h`, `forecast_wind_solar_error_lag_24h`, `residual_load_roll_mean_72h`
and `residual_load_roll_std_168h`. Example: target hour 23:00 with a 24 h lag reads 23:00 on
`DAY−1`, which is published after the forecast is issued.

This spec rebuilds spec 05's feature set **for spec 06's origin**, in a new notebook, and proves it
with the same truncation test spec 06 uses. It exports one CSV the regression notebook can load
later. Wiring that CSV into the regression notebook is a separate, later step (OUT).

Success means: the export holds one row per hour of `time_series`, every feature passes the
truncation leakage test, and each row carries its own cutoff, so a consumer can check that its
forecast setting matches.

### Section B — features, leakage test, export

6. **§3 `build_features(frame, errors)`**: one function that returns the 16 columns for every row
   of `frame`. It reads **only** its arguments, never the globals `time_series` or `smard_errors`,
   so §4 can call it on truncated data. The columns are listed in the Data table.
   - **Calendar / cyclical**: from each row's own local timestamp.
   - **Same-hour lags**: wall-clock shifts, `series.reindex(index − lag)`, not row shifts.
   - `vre_capacity_factor_lag_48h`: `renewables / (cap_wind_off + cap_wind_on + cap_solar)` at the
     same local hour two days earlier. Capacity is read at that **historical hour**, as in spec 05's
     edge case. It is a past ratio, and its year's capacity was published before that hour.
   - **Rolling features**: one value per delivery day, computed on the window that **ends at the
     day's last usable row**, `cutoff − RESOLUTION`, from `ROW_SETTING`. `min_periods` is the full
     count `n_obs(window)`, so a window spanning a spring-DST gap stays `NaN`, as in spec 05. The
     one value is broadcast to all the day's hours.
   - `forecast_wind_solar`: `fc_gen_wind_solar` at the target hour, the one input allowed to read
     the target hour itself (published by 18:00 on `DAY−1`).
7. **§3 mapping note.** A markdown table maps every spec 05 feature to its column here, with the
   reason for each change (Data table, "from spec 05" column). Spec 05's dropped and excluded
   candidates stay dropped and excluded, with a pointer to spec 05 rather than a repeat.
8. **§4 Leakage test by truncation**, following spec 06 Behaviour 8:
   - Draw `LEAKAGE_SAMPLE_DAYS` delivery days with `SEED`, from days whose features are all
     defined. Add the record's latest 1 January and latest spring-DST day.
   - For each day, cut the data at its cutoff: set measured columns (`wind_off`, `wind_on`,
     `solar`, `grid_load`, `residual_load`, `renewables` and `cap_*`) and every `errors` column to
     `NaN` where `available(t, cutoff)` is false. Keep `fc_gen_wind_solar` up to the end of `DAY`,
     and drop rows after `DAY`.
   - Rebuild the day's rows with `build_features` and assert they are **identical** to the rows
     built from the full data (`DataFrame.equals`, so `NaN == NaN`).
   - As a **control**, run the same test on spec 05's leaking definition of
     `residual_load_lag_24h`, for one sampled day. It must **fail**. That shows the test can catch
     the leak this spec fixes. Print both results.
9. **§5 Export and self-check.**
   - Write `data/features/residual_load_features_cutoff.csv` with `timestamp`, `cutoff` (the row's
     availability cutoff) and the 16 features. It is plain CSV (`sep=","`, `decimal="."`, UTF-8).
     Create `data/features/` if missing.
   - Read it back with a bare `pd.read_csv` and assert:
     - one row per `time_series` row, same timestamps
     - identical values
     - the `cutoff` column equals `ROW_SETTING["cutoff"]`
   - Closing self-check:
     - `features` has `len(time_series)` rows on the same index
     - `time_series` still holds exactly `SERIES + DERIVED`
     - cyclical values lie in `[−1, 1]` and `season_code` in `{0, 1, 2, 3}`
     - `vre_capacity_factor_lag_48h` lies in `[0, 1]` where not `NaN`
     - neither `fc_grid_load` nor `fc_residual_load` feeds any column
   - A short missingness table per column (hours and days `NaN`), with the reasons for each count.

## Edge cases

- **Why 48 h is safe.** The latest source of a `DAY−2` same-hour lag is 23:00 on `DAY−2`. That is
  before any cutoff on `DAY−1` as long as `issue_clock − actuals_lag ≥ resolution`. The §2.2 check
  verifies it on every row, so a change to `DATA_INFO` needs no change to this spec.
- **1 January.** `vre_capacity_factor_lag_48h` for delivery day 1 January reads 30 December, with
  that year's capacity: a historical ratio, correct as it is.
- **Spring DST.** A lag source at local 02:00 on a spring-DST day does not exist and stays `NaN`.
  Rolling windows spanning the gap have one row too few and stay `NaN`. The counts come from the
  data and are never hardcoded.
- **Warm-up.** The record's first days have no 168 h / 72 h / 7-day values. They stay `NaN`, never
  zero-filled.
- **Missing SMARD forecast or error hours.** `forecast_wind_solar` and
  `forecast_wind_solar_error_lag_48h` stay empty where their source is empty (2020-01-31 in the
  current snapshot). Nothing is interpolated.
- **`DATA_INFO` drift.** If the team changes `actuals_lag` in the regression notebook only, this
  export is built for the wrong cutoff. The `cutoff` column is the guard: a consumer asserts it
  equals its own `ROW_SETTING["cutoff"]`.
